## Known defects (observed in the code on 2026-10-27; reproduce each before fixing — this list is a floor, not a ceiling)

1. **Off-by-one** — `src/api/resolvers/articles.resolver.ts`: `slice(0, args.first - 1)` returns one article too few.
2. **"Invalid Date" in the feed and on the detail screen** — epoch-seconds dates arrive as digit strings (`article-4` visible today, `article-10` hidden by #1). `ArticleListItem` and `ArticleDetail` both call `new Date(article.datePublished)` directly; the list item's truthiness guard does not catch it.
3. **Crash on a null byline** — `ArticleListItem` calls `article.authors.map` with no guard (`ExpandedArticleCard` and `ArticleDetail` do guard). Latent until `article-13` reaches the feed, but the brief says the API is not well-formed, so it counts.
4. **Pull-to-refresh never stops** — `useRefreshControl` resets `refreshing` in an effect with `[]` deps, so it runs once, before any fetch (lint flags it).
5. **Interval leak** — `ArticleFeed.screen.tsx` starts a new `setInterval` on every `lastRefreshed` change and never clears any; the handle is unused (lint error).
6. **Listener leak** — `ArticleDetail.screen.tsx` adds an `AppState` listener per visit and never removes it; the handler uses `console.log` (lint error).
7. **Header shows the id** — `AppNavigator.tsx` sets `headerTitle: route.params.id` ("article-1").
8. **`0` word count crashes** — `{article.wordCount && (<Text>…)}` renders a bare `0` outside `<Text>` when the count is zero; the schema allows a nullable Int.
9. **Inline style object** — `ArticleListItem` spreads `styles.container` into a fresh object every render (lint error; also defeats `React.memo`).
10. **Secret-looking key in source** — `src/api/config.ts` exports an unused `analyticsConfig` with a hard-coded live-looking API key and logs config at import (lint error).
11. **Tokens persisted in plain text** — `session.slice.ts` ships dev auth tokens and the `root` persist config writes the whole store to AsyncStorage.
12. **Reading position is never restored** — the restore effect runs once on mount while `LoadingView` is showing, so the ScrollView ref is `null`; the position is written on every throttled scroll with no error handling. Minor.
13. **Opacity animation on the JS thread** — `ExpandedArticleCard` passes `useNativeDriver: false` for an opacity fade. Minor.
14. **No timeout handling** — with `simulateTimeout` the detail screen spins for 30 s with no way out. Polish.
15. **Raw error text** — the feed's error state shows `error.message` verbatim (`[GraphQL] Internal Server Error`). Polish.
16. **Test runner is broken** — see Environment facts. Tooling, Session 0.
17. **`BookmarkedArticles` route declared, no screen** — the brief's intended name for Part 2A.

## Traps — read before planning, re-read before each commit

- **Digit strings, not numbers.** The bad dates reach the app as `"1709251200"`, so a `typeof value === 'number'` branch never fires; parse digit-only strings by length. A real server could send any of these shapes — which is why the parser lives at the boundary, not in the mock.
- **The TypeScript types lie.** `types.ts` says `authors: Author[]` and `datePublished: string`; the schema says `[Author!]` (nullable) and `String!` holding anything. Trust the schema and the fixture, and make the types say what the data does.
- **Three places render a date; one formatter.** List item, detail screen, and soon the bookmarks screen. Fix it once.
- **`{value && <Text/>}` crashes on `0`** ("Text strings must be rendered within a <Text> component"). Use explicit null checks for numbers.
- **urql's document cache is memory-only.** `reexecuteQuery({requestPolicy: 'network-only'})` keeps stale `data` while `fetching` is true — good for pull-to-refresh — but nothing survives a restart, and the detail screen's `if (fetching)` hides existing content during a retry. "Offline after relaunch" means an empty feed unless you persist a copy.
- **Jest and ESM.** Override `transformIgnorePatterns` in `jest.config.js` to extend the preset's negative lookahead with `@react-navigation` and `@react-native-async-storage` (and whatever else fails with "Unexpected token 'export'"). AsyncStorage v3 ships no Jest mock: `jest.mock` it with a small in-memory implementation in a setup file. Mock `react-native-screens` and safe-area only if you render a navigator — prefer not to. For urql, `jest.mock('../graphql/queries')` returning `[{data, fetching, error}, jest.fn()]` beats standing up a client.
- **Share on two platforms.** `url` is iOS-only; Android reads only `message`. `dismissedAction` is only ever returned on iOS; Android always resolves `sharedAction`. `Share.share` rejects on failure, so `try/catch`. On the simulator the sheet opens with few targets; that is enough to verify.
- **redux-persist details.** A new slice is persisted automatically under `root`, together with the dev tokens, unless you whitelist. `PersistGate loading={null}` means a blank frame during rehydration; keep it or add a loading view, but do not block the feed on it. If a persisted shape changes between sessions, bump `version` with a `migrate`; the simulator keeps the previous state.
- **Commitlint.** `type(scope): subject` with a type from config-conventional; start the subject in lowercase; keep the header under 100 characters; one blank line before any body.
- **Hooks rules.** `exhaustive-deps` is an error here. Depend on what you use; use `useRef` for values you intentionally do not want to retrigger on.
- **Memoized rows and bookmarks.** `ArticleListItem` is wrapped in `React.memo`; pass `isBookmarked` as a prop from a selector in the screen, or the row will not update when the bookmark toggles.
- **Untracked does not mean safe.** `docs/` and the root `AGENTS.md` show up in `git status` forever; one `git add .` ships them. Stage by name.
- **Xcode 27.** Simulators come from Device Hub, not Simulator.app; `npx react-native run-ios` works as of the fix commit. If a native build breaks, stop and report rather than rewriting the native projects.
- **The auto-mode classifier blocks some commands** (in earlier projects: removing volumes, some reads). Do not work around it: ask me to run the exact command with the `!` prefix and continue with its output.
- **Budget.** The reviewers read the chat logs. A tight log that fixes the right things with tests beats a long one that gold-plates. Timebox each session; log the time.

## Working style

- **Reproduce, fix, test, commit — in that order.** After each gate, state what you verified and how, then continue. Do not wait for approval for routine work; stop only for a new dependency beyond the pre-approved one, a change under `ios/` or `android/`, a push, or anything that would touch `README.md` or `articles.json`.
- **Subagents.** The codebase is twenty files: do the audit and the fixes yourself. Use subagents where they pay: an independent review of the session's diff before you close the session (hand it the diff and the README's seven evaluation criteria, not your conclusions), and, in Session 3, independent polish items in separate worktrees when their file sets do not overlap. Never more than two or three at once; never spawn one to "explore".
- When this prompt and reality disagree (a version, an API, a behaviour), reality wins: stop, note it in `docs/AGENTS.md`, continue. When this prompt and `README.md` disagree, the README wins.
- Keep the plan honest. If a gate cannot be met within the budget, say so and log why instead of marking the session done.
- Every change must be explainable by me in one sentence in an interview. Prefer plain code; comment only the non-obvious (why digit strings are treated as epoch seconds). No new abstractions beyond the parse layer, the slice and the two buttons.
- Finish every session with a short summary: what changed (commits), what was verified, what is next, what needs me.
